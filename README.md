# AI Visibility Checker

Free tool: does ChatGPT recommend your brand? Asks ChatGPT (OpenAI + web search) 3 buyer-style questions in your category and reports mentions, rank, competitors and cited sources.

For weekly tracking across ChatGPT, Gemini & Perplexity, see the [AI Visibility Tracker](https://apify.com/crunchy_galaxy_qcr/ai-visibility-tracker).

Next.js on Vercel. Cost guards: per-IP daily limit, global daily cap, monthly budget ceiling, 24h result cache (Vercel Blob). Env: `OPENAI_API_KEY`, `BLOB_READ_WRITE_TOKEN`, `HASH_SALT` (required in production and on Vercel preview), optional `PER_IP_DAILY`, `GLOBAL_DAILY`, `LAUNCH_DAYS` (comma list of UTC dates, default 2026-11-10..12), `LAUNCH_DAILY` (default 150), `MONTHLY_BUDGET_USD`, `LAUNCH_MONTH` + `LAUNCH_MONTHLY_BUDGET_USD` (default $20 for 2026-11). See `.env.example`.

`HASH_SALT` is mixed into the hashes for per-IP rate-limit keys and the 24h result cache. Set a long random value on the Vercel Production and Preview targets (it is already configured there). Do not commit it, and do not log it. Local `next dev` and `npm test` use a built-in dev-only fallback when it is unset. A production or preview runtime refuses the check with HTTP 503 instead of using that fallback. The salt is read on the request, not during `next build`, so a missing runtime secret does not fail the deploy. Changing `HASH_SALT` resets existing rate-limit and cache keys, so existing limits reset after that deploy. It also encrypts report-email records and raw answers. Changing it makes those records unreadable.

Report email is off unless `EMAIL_CAPTURE_ENABLED=1`, `RESEND_API_KEY`, and `RESEND_FROM` are all set. `RESEND_FROM` has to be an address on a domain already verified in the Resend account. The one-time report price stays hidden unless `PAID_REPORT_ENABLED=1`. Leave that unset until the price is approved.

Monthly tracking is $24/month for one saved brand: a weekly ChatGPT web-search re-check, emailed with the run count and the raw answers. The card, the score-row "Track this brand weekly" banner, and `POST /api/checkout` stay hidden unless `TRACKING_TIER_ENABLED=1` (checkout and `POST /api/tracking/offer` return 404 otherwise). The banner scrolls to the card for the brand just checked. `POST /api/tracking/offer` accepts only `{ "event": "impression" }` or `{ "event": "click" }` from the same origin. Checkout starts are counted when a Stripe Checkout Session is created. Completed subscriptions are counted when `checkout.session.completed` (paid) or `checkout.session.async_payment_succeeded` activates a subscription that was not already active. `invoice.paid` renewals are not counted again. Counts are one Blob object per UTC day at an unguessable key (`offer-metrics/<salted hash>/<date>`). The object is four integers plus a write budget, capped so a burst cannot create more objects or grow the value. It does not include a brand, email, or IP. `GET /api/admin/tracking-metrics` returns the last 14 UTC days. It requires `Authorization: Bearer` matching `CRON_SECRET` or `ADMIN_SECRET` (each at least 16 characters), is rate-limited, and sends `Cache-Control: no-store`. Checkout is a Stripe Checkout Session in subscription mode. It requires a confirmed email and reads `STRIPE_SECRET_KEY` and `STRIPE_TRACKING_PRICE_ID`. `POST /api/stripe/webhook` verifies `STRIPE_WEBHOOK_SECRET` and rejects unsigned requests. Activate on `checkout.session.completed` (paid), `checkout.session.async_payment_succeeded`, and `invoice.paid`. Deactivate on `customer.subscription.deleted`, `customer.subscription.updated` (canceled, unpaid, incomplete_expired, paused, or past_due), `customer.subscription.paused`, `invoice.payment_failed`, `checkout.session.async_payment_failed`, `charge.dispute.created`, `charge.refunded`, and `radar.early_fraud_warning.created`. Handled events are idempotent on the Stripe event id. Cancel anytime from the billing portal link in each tracking email (`GET /api/tracking/portal`) or the signed manage page (`/tracking/manage`). The unsubscribe link cancels the Stripe subscription and deletes the address.

`GET /api/cron/tracking` runs Monday 15:00 UTC (`vercel.json`, Vercel Cron). It requires `Authorization: Bearer <CRON_SECRET>`. It re-checks only active paid subscribers, stores that run's raw answers on the subscriber record, and sends the result with a unique per-send Resend idempotency key. Spend is charged to `TRACKING_MONTHLY_BUDGET_USD` (default $10) plus a 6-day cap per subscriber. It does not read or write the free-checker month counter, including the November 2026 $50 cap. This app does not create the Stripe product or price.

`POST /api/lookup` asks one ChatGPT web-search question about a market and lists the brands it names. Lookups share the per-IP daily limit, the global daily cap, and the monthly dollar counter with brand checks. November 2026 spend cannot exceed $50, including when `LAUNCH_MONTHLY_BUDGET_USD` is set higher. A lookup is refused when a limit is already hit, when those counters cannot be read, or when recorded spend plus the lookup reserve (`EST_COST_PER_LOOKUP`, default $0.12) would exceed the month budget. After a successful call the reserve is replaced with the measured cost. The same normalized market is cached for 24 hours and is not charged again. URLs, instruction-shaped text, and junk are rejected and are never fetched.
